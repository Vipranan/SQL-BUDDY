SQL BUDDY - Natural Language to SQL Query System
================================================

OVERVIEW
--------
SQL Buddy is a FastAPI-based web application that converts natural language queries 
(including non-English languages) into SQL queries and executes them against registered databases.

ARCHITECTURE FLOW
-----------------
User Query → Translation → Schema Loading → SQL Generation → Validation → Execution → Results


CORE FILES AND THEIR ROLES
---------------------------

1. app.py
   - Main FastAPI application entry point
   - Defines REST API endpoints for querying and database management
   - Orchestrates the entire query pipeline
   - Endpoints:
     * POST /query - Process natural language queries
     * GET /databases - List all registered databases
     * POST /databases/add - Register a new database
     * POST /databases/select - Set active database
     * GET /databases/local/sqlite - Discover local SQLite databases

2. translator.py
   - Detects the language of user input using langdetect
   - Translates non-English queries to English using Ollama LLM
   - Preserves database-specific terminology during translation
   - Supports Tamil, Hindi, and other languages

3. db_registry.py
   - Manages database registration in db_registry.json
   - Functions:
     * list_databases() - Get all registered databases
     * add_database() - Register a new database connection
     * set_active_database() - Switch active database
     * get_active_database() - Retrieve current active database

4. db_context.py
   - Loads database schema using SQLAlchemy inspection
   - Extracts tables, columns, primary keys, and foreign keys
   - Executes SQL queries against the active database
   - Functions:
     * load_schema() - Extract database structure
     * execute_query() - Run SQL and return results
     * get_active_db_context() - Get active DB with schema

5. schema_extractor.py
   - Standalone script for extracting PostgreSQL database schema
   - Uses SQLAlchemy inspector to analyze database structure
   - Outputs schema dictionary with tables, columns, and relationships
   - Note: This is a utility script, not used in the main flow

6. prompt_builder.py
   - Converts database schema dictionary into human-readable text
   - Formats tables, columns, primary keys, and foreign keys
   - Output is used as context for the LLM to generate accurate SQL

7. sql_generator.py
   - Uses Ollama LLM (qwen2.5:7b model) to generate SQL queries
   - Takes English query + schema prompt as input
   - Returns PostgreSQL-compatible SQL query
   - Instructs LLM to use only existing tables/columns

8. sql_validator.py
   - Security layer to prevent dangerous SQL operations
   - Functions:
     * clean_sql() - Removes markdown code fences from LLM output
     * is_safe_sql() - Validates query is SELECT-only
   - Blocks: DROP, DELETE, UPDATE, INSERT, ALTER, TRUNCATE, GRANT, REVOKE

9. sql_executor.py
   - Legacy standalone SQL executor for PostgreSQL
   - Uses SQLAlchemy to execute queries
   - Note: Replaced by execute_query() in db_context.py

10. sqlite_discovery.py
    - Scans directory for SQLite database files
    - Identifies .db files and validates them as SQLite databases
    - Used by /databases/local/sqlite endpoint

11. db_registry.json
    - JSON file storing registered database connections
    - Structure:
      {
        "active": "database_name",
        "databases": {
          "name": {"type": "sqlite", "url": "sqlite:///path.db"}
        }
      }


SUPPORTING FILES
----------------

12. schema_extractor_sqlite.py
    - SQLite-specific schema extraction utility

13. sql_executor_sqlite.py
    - SQLite-specific query executor utility

14. test_*.py files
    - Unit and integration tests for various components
    - test_chinook.py - Tests with Chinook sample database
    - test_db.py - Database connection tests
    - test_end_to_end.py - Full pipeline tests
    - test_prompt.py - Prompt building tests
    - test_sql_generation.py - SQL generation tests
    - test_translation.py - Translation tests

15. web/index.html
    - Frontend HTML interface for the application
    - Served by FastAPI using Jinja2 templates

16. *.db files (chinook.db, people.db, world.db)
    - Sample SQLite databases for testing

17. world.sql
    - SQL dump file for world database


QUERY PROCESSING PIPELINE
--------------------------

1. User submits query via POST /query
2. translator.py detects language and translates to English
3. db_context.py loads active database schema
4. prompt_builder.py formats schema for LLM
5. sql_generator.py generates SQL using Ollama
6. sql_validator.py validates SQL is safe (SELECT only)
7. db_context.py executes SQL on active database
8. Results returned as JSON with columns and rows


DEPENDENCIES
------------

- FastAPI: Web framework
- SQLAlchemy: Database abstraction and inspection
- Ollama: Local LLM for translation and SQL generation
- langdetect: Language detection
- sqlparse: SQL parsing and validation
- psycopg2: PostgreSQL adapter
- Uvicorn: ASGI server


SETUP REQUIREMENTS
------------------

1. Install Python dependencies: pip install -r requirements.txt
2. Install Ollama: https://ollama.ai
3. Pull LLM model: ollama pull qwen2.5:7b
4. Configure database in db_registry.json
5. Run: python app.py or uvicorn app:app --reload


SECURITY FEATURES
-----------------

- SQL injection prevention via sqlparse validation
- Only SELECT queries allowed
- Dangerous keywords blocked (DROP, DELETE, etc.)
- Markdown code fence removal from LLM output


EXTENSIBILITY
-------------

- Supports multiple database types (PostgreSQL, SQLite)
- Multi-language query support via translation
- Database registry allows switching between databases
- Schema-aware SQL generation prevents hallucination
